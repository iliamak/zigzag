# Pikabu Игры SDK — заметка для агентов

Читать перед любыми изменениями, связанными с публикацией, рекламой, монетизацией, сохранениями, авторизацией.
Источник: https://games.pikabu.ru/sdk/docs (собрано 2026-09-20).

## Быстрый старт
1. Требования (тех + контент) → 2. Подключить SDK → 3. Студия (games.pikabu.ru/studio) →
4. Секретный ключ → 5. Тестовое окружение + модерация → 6. Выплаты.

## Подключение SDK
- Скрипт: `<script async src="https://games.pikabu.ru/sdk/sdk.js" onload="initSDK()">`
- Работает ТОЛЬКО внутри страницы игры на платформе или в тестовом окружении Студии. Вне — не работает.
- `const sdk = await PkbSDK.init()` — один раз. Дальше объект `sdk`.
- `sdk.gameStarted()` — после загрузки ресурсов и первого экрана. Обязательно.
- Игра обязана работать с включённым блокировщиком рекламы (все вызовы ads через canShow, без падений).

## Реклама (sdk.ads) — 3 формата
Общий шаблон: `canShow()` перед каждым показом → пауза игры+звука → `show()` → resume.
- `isSupported` — статичен на сессию. `canShow()` — вызывать прямо перед показом.
- `show()` → `{rendered: true} | {rendered: false, reason}`. Причины: NOT_SUPPORTED, IN_PROGRESS, UI_BUSY, COOLDOWN_ACTIVE, INVALID_GAME_STATE, UNKNOWN.
- Не показывать техошибки игроку. Не оставлять на паузе если не открылось. Fallback: продолжить игру.
- Preloader: только до `gameStarted()`, только мобайл. Параллелить с загрузкой ресурсов. Самый дешёвый, сильнее бьёт по первому впечатлению.
- Fullscreen: паузы геймплея (между уровнями, после победы/поражения, возврат в меню). Закрытие после 3 сек. Кулдаун 120 сек. НЕ во время активного управления (фрод-риск, снимут доход). Короткие уровни — показывать через 2–3 уровня, не после каждого.
- Rewarded: ТОЛЬКО по явному клику игрока (кнопка «+100 монет»). Таймер 10 сек. Самый дорогой, но убивает удержание. Награда только при `result.reward === true`. Ограничений частоты нет.
- Реклама необязательна для публикации. Нет вызова — нет монетизации.

## Игрок и авторизация (sdk.player / sdk.auth)
- `sdk.player`: `id` (уникален на игру; неавторизованный — локальный, после авторизации может смениться), `name`, `avatar`, `isAuthorized`, `getSignedData()`.
- `id` — ключ для хранения прогресса на СВОЁМ backend. При авторизации mid-session перечитать `sdk.player.id`.
- Событие `userAuthorized` (`sdk.once/on('userAuthorized', ...)`). Выход из аккаунта в игре не поддерживается.
- `sdk.auth.openAuthDialog()` — окно авторизации; игрок может закрыть без входа → проверять `isAuthorized` после.
- Авторизация обязательна только для покупок. Геймплей без обязательной авторизации (иначе режут метрики). Если нужна — сначала «приветственный уровень», потом диалог.
- Подписи: `getSignedData()` → JWT HS256, проверка только на backend секретным ключом из Студии (никогда в клиенте). Payload игрока: avatar, id, isAuthorized, name.

## Покупки (sdk.store)
- Товары задаются в Студии («Внутриигровые товары»): id/тег, название, цена, тип.
- Типы: consumable (монеты, сундуки — много раз) / non_consumable (отключение рекламы, премиум — один раз).
- `getProducts()` — актуальные цены (price в КОПЕЙКАХ, currencyCode всегда RUB, formattedPrice «50 ₽»).
- `purchase({productId, developerPayload?})` → `{success, purchase | reason}`. Причины: USER_CANCELLED, USER_UNAUTHORIZED, UI_BUSY, IN_PROGRESS, INVALID_PRODUCT_ID, NON_CONSUMABLE_ALREADY_OWNED, UNKNOWN. Неавторизованному сначала откроется авторизация.
- Обработка: purchase → `purchase.getSignedData()` → свой backend проверяет подпись → начисляет → для consumable `consumePurchase(purchaseId)` ТОЛЬКО после подтверждения backend. Непотреблённые consumable висят в `getPurchases()` — дообработать при следующем запуске.
- Тест: в тестовом окружении оплаты эмулируются попапом (успех/неуспех), в статистику не идут.

## Техтребования (блокеры модерации)
- Хостинг билда — СВОЙ сервер + ссылка в Студии. Загрузки билда на серверы Пикабу нет. Альтернатива без сервера — GamePush.
- Chrome / Яндекс / Safari последних версий, десктоп + мобайл. Адаптив, без вылезания UI.
- Русский интерфейс по умолчанию.
- Автопауза: смена вкладки, реклама, окно авторизации, оплата. Звук в фоне — выкл.
- Работа с адблоком. Без обязательной авторизации/регистрации в сторонних сервисах.
- ОБЛАЧНЫЕ СОХРАНЕНИЯ ОБЯЗАТЕЛЬНЫ. В SDK нет готового cloud-save API — только `player.id` (+ signedData) как ключ под СВОЙ backend. Без backend модерацию могут не пройти. Вариант: GamePush.
- Чек-лист перед отправкой — в доке `requirements/tech`.

## Контент (блокеры модерации)
- Без нарушения авторских прав. Без сторонних ссылок (кроме поддержки). Наша VK/Telegram-шаринговая логика — кандидат на удаление.
- Иконки: квадрат от 1024×1024 + горизонталь от 1920×1080 (16:9), jpg/png/webp до 10 Мб.
- Без мата/наготы/жести/кликбейта. Суммарный геймплей ≥ 30 минут.
- В названиях игры и товаров — без англицизмов (кроме товарных знаков). «зигзаг» — ок.
- Бан: секс-контент, казино/азарт, политика, религия-конфронтация, ненависть.
- Скриншоты: до 10 (оптимально 5), 1280×720 или 720×1280, 16:9/9:16.

## Фичеринг (продвижение после публикации)
- Прогрессия/сложность/цели; прохождение ≥ 30 мин; без багов UI; звук с кнопкой mute; загрузка < 10 сек; удержание (достижения/лидерборд/прогресс); обновления + фиксы; мобайл-удобство.
- Витрины: «Лучшие» (топ-10, авто 1 сутки / ручной 7–12 дней), промо в ленте Pikabu.ru (метрики/доход), «Выбор редакции» (авторские), «Новые игры» (первые дни после публикации, один раз).
- Заявки: games@pikabu.ru.

## Студия / модерация / деньги
- Карточка игры: название ≤ 50 симв, ссылка на билд, устройства, ориентация, возрастной рейтинг, жанр, краткое ≤ 250 симв, иконки, «Об игре» ≤ 10000, «Как играть» ≤ 10000, SEO ≤ 250, скриншоты.
- Секретный ключ: один на игру, хранить вне клиента, при утере — только новый.
- Тестовое окружение: ссылка на билд → тестовая ссылка с заглушками рекламы/оплат + расширенный лог. Без авторизации доступна (инкогнито для неавторизованных). После отладки — удалить ссылку.
- Модерация: сначала заполнить реквизиты выплат (Настройки — Документы), иначе не отправить. Кнопка «Отправить на модерацию» лочит карточку. Срок до 3 рабочих дней. После успеха — СРАЗУ публикация в каталоге. Статусы: черновик / на модерации / отклонена / опубликована / не опубликована (снять — только через games@pikabu.ru).
- Деньги: разработчику 50% чистого дохода (после НДС, эквайринга ~2,5%, налога на рекламу). Реклама + IAP в статистике. Выплаты 1–10 числа по будням. Только ИП/ООО/самозанятые РФ + счёт в банке РФ. Оферта: games.pikabu.ru/page/sdk-offer.

## Для нашей игры («зигзаг», Pikabu-версия; прототип — «шаг»)
- Убрать: VK Bridge, ежедневный seed/стрики/напоминания/друзья-коды, сторонние шаринги (оставить только поддержку), ежедневный лок «одна игра в день».
- Добавить: 100 детерминированных уровней (seed = индекс), экран выбора уровней, прогресс (localStorage + backend-заглушка под player.id), SDK init + gameStarted, fullscreen между уровнями (каждые 2–3, с кулдауном), rewarded за подсказки, non_consumable «отключение рекламы», автопауза таймера на ads/auth/hidden-tab, mute-кнопка, работа с адблоком.
- Риски запуска за 2 дня: модерация до 3 дней (уложиться = только отправка); облачные сохранения требуют backend; реквизиты/статус нужны до модерации; нужен свой хостинг URL.
