## 0. Диагноз в цифрах (почему рампа плоская)

Метрика «ложных ходов» (decoy = допустимый ход, не ведущий по решению) — единственная, что коррелирует с работой решателя: **r = 0,95 с log(solverNodes)**.

| ось | 4×4 | 5×5 | 6×6 | 7×7 |
|---|---|---|---|---|
| флажков на клетку | 0,25 | 0,22–0,24 | 0,19–0,22 | 0,16–0,18 |
| ложных ходов на клетку (decoy/cell, медиана) | 0,40 | 0,42 | 0,46 | 0,52 |
| **ложных ходов на одну развилку** | **0,90** | **0,84–1,00** | **0,74–0,90** | **0,90** |
| точек решения (≥2 хода) | 5 | 8 | 14 | 20 |
| solverNodes (медиана) | 157 | 442 | 2 573 | 33 565 |
| стенок (медиана) | 1 | 3 | 3 | 5 |

Пять фактов, объясняющих «на 40-х легче, чем на 5×5» (сходится с диагнозом PROGRESSION §1: один генератор = один навык):

1. **Локальная нагрузка не растёт вообще.** Ложных ходов на одну развилку: 0,90 → 0,90 (r = −0,01 с объёмом поиска). Растёт только *число* развилок (5 → 20) и клеток (16 → 49). Игрок делает то же действие больше раз, а не более сложное — это читается как «длиннее», не «труднее».
2. **Лесенка держит плотность флажков постоянной** (0,25 → 0,17 флажка/клетку). Единственная ручка с r = 0,95 (флажки) намеренно выровнена по площади — то есть нейтрализована.
3. **Стенки работают как смягчитель — по построению.** Стенки ставятся только на рёбра вне решения, значит каждая может убить лишь ложный ход и никогда правильный: она способна только вычитать варианты. Замер: 5×5 при 6 флажках — 0 стенок → 861 node / 0,458 decoy/cell; 4 стенки → 271 / 0,375; 8 стенок → 128 / 0,25. При этом `score = … + walls*5` **начисляет баллы за смягчение**, а на входе в 7×7 стенок сразу 6 — на шве 6×6→7×7 плотность ложных ходов **падает**: #66–70 = 0,514 → #71–75 = 0,479.
4. **`score` меряет не то и по-разному на разных размерах.** Вклад слагаемых в сумму по размеру: `maxGap*10` — 93 % / 81 % / 61 % / 13 % (4×4 → 7×7), `nodes/100` — 2 % / 6 % / 27 % / 84 %. Порядок внутри 4×4–6×6 задаёт maxGap и стенки, внутри 7×7 — комбинаторика поиска. При сортировке по `score` разброс decoy/cell 0,33–0,57 внутри размера = почти случайный порядок.
5. **Запас внутри размера ограничен, но не исчерпан.** Максимум decoy/cell без новых механик: 0,47 (4×4, отгруженный максимум), 0,58 (5×5), 0,63 (6×6), 0,69 (7×7) — это p90 прогона «оптимальные флажки + точечные стенки». Абсолютный предел с двумя флажками выше (0,63 / 0,69 / 0,73), но там единственность не держится ни разу из 40. Отгруженные медианы: 0,40 / 0,42 / 0,46 / 0,52 — резерв +20–25 %, и он упирается в единственность решения.

**Ключевой конфликт:** больше ложных ходов → больше решений → нужны стенки для единственности → стенки убивают ложные ходы. Генератор торгуется вслепую (случайное число стенок), поэтому застревает в полосе decoy/cell 0,40–0,55 на всех размерах. Лечится не механизмами в первую очередь, а точечными стенками (§3, п.3): замерено 5×5 → 2 стенки, 6×6 → 4–5, 7×7 → 9–10, плотность остаётся на максимуме.

**Запас фабрики:** приёмка падает при разрежении флажков: 7×7 с 9 флажками — 1 из 400, с 6–8 — 0 из 400; 6×6 с 5–6 флажками — 1–8 из 800. «Урезать флажки и подождать» не работает — нужен целевой перебор раскладки.

## 1. Кандидаты в механики

Формат: **название → правило (1 фраза) → second-level test (чем 2-й уровень отличается от 1-го; не прошла — в мусор) → процедурная генерация → пак.**
`[замерено]` — проверено прогоном генератора/решателя, `[не проверено]` — нужен прототип.
Правило паков (PROGRESSION §2): одна новая механика на пак, не чаще раза в 10 уровней → в раскладке 8 механик на паки 2–9; остальные — резерв на второй проход.

### М1. Проёмы (односторонние ворота) — *кандидат PROGRESSION #5*
- **Правило:** часть внутренних рёбер — «двери»: пройти ребро можно только в одну сторону, обратно нельзя.
- **2-й уровень:** на 1-м один проём стоит на единственном очевидном ходе (обучает чтению стрелки); на 2-м проём перекрывает возврат из кармана, и маршрут «сначала зайду, потом вернусь» становится невозможен — надо читать покрытие на 4–5 клеток вперёд. Если 2-й отличается только числом проёмов — в мусор.
- **Процедурно:** да — дверь вешается на ребро вне решения, в DFS добавляется фильтр по направлению прохода; единственность проверяет тот же решатель. `[не проверено]`
- **Пак:** 5.

### М2. Сквозные клетки
- **Правило:** на клетке с меткой нельзя поворачивать — линия входит и выходит по одной прямой.
- **2-й уровень:** на 1-м одна сквозная клетка на пути; на 2-м сквозная клетка упирается в угол поля, «жадный» обход края перестаёт работать и нужен S-образный заход. Если 2-й — просто ещё сквозная клетка — в мусор.
- **Процедурно:** да — состояние DFS = направление входа, раскладка на прямых участках решения. `[не проверено]`
- **Пак:** 6.

### М3. Клетки-повороты
- **Правило:** на клетке с уголком линия обязана повернуть.
- **2-й уровень:** на 1-м один уголок в открытом поле; на 2-м два уголка в одном сегменте между флажками, где места хватает ровно на один «крюк» — порядок обхода становится однозначным. Если 2-й — просто +1 уголок — в мусор.
- **Процедурно:** да — тот же фильтр, что у М2 (состояние = направление), общий код. `[не проверено]`
- **Пак:** резерв (второй проход; если паку 6 понадобится вторая механика — идёт туда после М2).

### М4. Форма поля (полиомино, дырки-перешейки)
- **Правило:** поле — не квадрат, а фигура с вырезами и узкими перешейками; линия по-прежнему обязана обойти все клетки.
- **2-й уровень:** на 1-м простая Г-фигура (правило «обойти всё» видно сразу); на 2-м перешеек шириной в одну клетку — ошибка на входе в перешеек отрезает целую область, и это видно только через 6 ходов. Если 2-й — просто другая фигура без перешейка — в мусор.
- **Процедурно:** да — маска клеток, решатель не меняется (клетки вне маски недоступны), генератор масок: прямоугольник с вырезами и П/Г-фигуры. `[не проверено]`
- **Пак:** 2.

### М5. Две нити (две цветные последовательности)
- **Правило:** флажки двух цветов, внутри каждого цвета номера идут по возрастанию, порядок между цветами свободный.
- **2-й уровень:** на 1-м цвета чередуются, порядок почти очевиден; на 2-м два флажка одного цвета на разных концах поля, и «жадный» сбор по цвету запирает противоположную область. Если 2-й отличается только раскраской — в мусор.
- **Процедурно:** да — два счётчика порядка в решателе; цена — решений становится больше, отбор дороже. `[не проверено]`
- **Пак:** резерв (второй проход).

### М6. Флажки-близнецы
- **Правило:** два флажка с одинаковым номером можно пройти в любом порядке.
- **2-й уровень:** на 1-м близнецы стоят рядом (выбор виден сразу); на 2-м они в противоположных углах, и один из двух порядков оставляет неприкрытую клетку. Если 2-й — просто ещё пара близнецов — в мусор.
- **Процедурно:** да — правило «номер не меньше предыдущего»; близнецы плодят решения, отбор дороже вдвое. `[не проверено]`
- **Пак:** резерв (смягчитель ритма, не усилитель).

### М7. Лимит поворотов
- **Правило:** весь путь строится не более чем за K поворотов, K показано рядом с полем.
- **2-й уровень:** на 1-м K с запасом в 3 поворота (правило видно, но не давит); на 2-м K впритык — привычный обход края даёт на один поворот больше и умирает на последних клетках. Если 2-й — просто K меньше без нового конфликта — в мусор.
- **Процедурно:** да — счётчик поворотов в состоянии DFS, K считается от оптимума автоматически (оптимум + дельта) — непрерывная ручка крутизны внутри одного размера. `[не проверено]`
- **Пак:** 7.

### М8. Стрелки входа на флажках
- **Правило:** к флажку можно подойти только с указанной стороны.
- **2-й уровень:** на 1-м стрелка совпадает с очевидным заходом; на 2-м две стрелки «ссорятся»: заход по первой отрезает подход ко второй, нужен обход через дальний край. Если 2-й — просто вторая стрелка в стороне — в мусор.
- **Процедурно:** да — фильтр последнего ребра перед флажком, раскладка по решению. `[не проверено]`
- **Пак:** 9.

### М9. Свободный старт (без «1»)
- **Правило:** стартовый флажок не помечен — линия может начинаться с любого флажка, дальше номера по возрастанию от выбранного.
- **2-й уровень:** на 1-м старт однозначен (остальные варианты сразу ломают покрытие); на 2-м есть два возможных старта, и «красивый» неверный отрезает угол только через 8 ходов. Если 2-й — просто отсутствие цифры 1 — в мусор.
- **Процедурно:** да — перебор стартов в решателе (стоимость ×N), уникальность = ровно одна пара (старт, путь). `[не проверено]`
- **Пак:** резерв (второй проход; механик и так 8 на 8 паков).

### М10. Мостики через край — *безопасная форма кандидата PROGRESSION #4*
- **Правило:** две отмеченные клетки на краях считаются соседними — линия уходит за край и продолжается с парной клетки.
- **2-й уровень:** на 1-м мостик на очевидном маршруте; на 2-м ближний мостик манит как короткий путь, но ведёт к запиранию клетки, а рабочий — дальний. Если 2-й — просто второй мостик — в мусор.
- **Процедурно:** да — добавляются рёбра в граф, единственность проверяет тот же решатель; добавляет ходы, значит добавляет ложные ходы — по нашей метрике это усилитель. `[не проверено]`
- **Пак:** 8.

### М11. Обязательные клетки — *кандидат PROGRESSION #3*
- **Правило:** через клетку с меткой (без номера) линия обязана пройти.
- **2-й уровень:** на 1-м обязательная клетка на очевидном ходу (учит читать точку); на 2-м она стоит так, что каркас идёт «против шерсти» привычке — сначала надо уйти в дальний угол. Если 2-й — просто вторая точка — в мусор.
- **Процедурно:** да — ограничение «клетка ∈ пути»: в проверку связности добавляется прунинг «непокрытые обязательные клетки недостижимы → стоп» + финальная проверка покрытия. `[не проверено]`
- **Пак:** 4. **Важно:** это подсказка (сужает дерево), а не усилитель — пак 4 добирает плотность за счёт §3 п.2–3.

### М12. Запертые клетки (дыры)
- **Правило:** отдельные клетки поля закрыты, заходить нельзя.
- **2-й уровень:** на 1-м дырка в углу (визуально понятно); на 2-м дырка в центре режет поле так, что обход «по кругу» требует выбрать сторону первой. Если 2-й — просто дырка в другом месте — в мусор.
- **Процедурно:** да — исключить клетки из графа, решатель не меняется. `[не проверено]`
- **Пак:** 3 (первое «новое» геометрическое событие в 5×5).

### М13. Крест (самопересечение)
- **Правило:** в отмеченной клетке линия может пройти над собой — клетка считается пройденной дважды.
- **2-й уровень:** на 1-м один крест без выбора; на 2-м крест выгоден только при конкретном порядке обхода ветвей. Если 2-й — просто второй крест — в мусор.
- **Процедурно:** трудно — ломает модель «гамильтониан + массив visited», нужен второй слой посещённости, порядок ветвей и новая схема в JSON. `[не проверено]`
- **Пак:** не в первую волну (кандидат на 11+, после запуска).

### М14. Порталы (телепорт через центр)
- **Правило:** дойдя до клетки-портала, линия продолжается из парной клетки.
- **2-й уровень:** на 1-м портал на периферии; на 2-м портал экономит 6 клеток, но запирает регион — правильный ответ «не пользоваться». Если 2-й — просто пара порталов — в мусор.
- **Процедурно:** да технически (рёбра-телепорты), но единственность хрупкая, а линия визуально «рвётся» и читается как баг. `[не проверено]`
- **Пак:** не брать (эффект закрывает М10 без разрыва линии).

### М15. Стена-улика (структурные стенки вместо случайных) — *переформулировка кандидата PROGRESSION #1*
- **Правило:** стенки ставятся не пачкой случайных рёбер, а точно на рёбра ложных проходов — чтобы сузить поле выбора, не убивая развилки.
- **2-й уровень:** на 1-м одна стена на пути ложного хода (учит «стена = улика»); на 2-м стена делает ложный ход дорогим — убивает не сразу, а на возврате, заставляя переигрывать 5 ходов. Если 2-й — просто больше стен — в мусор.
- **Процедурно:** да — решатель уже отдаёт второе решение, стенка вешается на первое расхождение с сохранённым решением. `[замерено: 5×5 — 2 стенки, 6×6 — 4–5, 7×7 — 9–10; единственность 100 % / 100 % / 64–76 %]`
- **Пак:** 4–5. Это не механика для игрока, а замена ручки генератора — идёт в дешёвый трек (§3).

### Отбраковано сразу
- Таймеры/«успей за N секунд»/экшн-угрозы — запрещено рамками.
- «Лимит длины линии» — длина всегда равна числу клеток, ручки нет.
- «Сдвиг/вращение поля по ходу» — ломает предсказуемость, нечитаемо на телефоне.
- «Скрытые стенки / туман» — информационный шум и нечестность, противоречит PROGRESSION §7 / FR-4.
- «Динамические препятствия» — нужны состояние и таймер, это не Zip.
- «Бусты/заморозки за рекламу» — мета-экономика, не механика уровня; в FR-6 не считается.

## 2. Паковая раскладка 100 уровней

**Гейты и правила паков:**
- **Teach-гейт «механика обязательна» (PROGRESSION §2, практика Valve):** на T-уровнях решатель запускается с **выключенной** механикой и должен найти 0 решений. Иначе уровень проходится «не поняв» — такой teach в мусор. Автоматизируется: 1 доп. прогон решателя на уровень.
- **Одна новая механика на пак** (не чаще раза в 10 уровней) — 8 механик на паки 2–9.
- **Экзамен = комбинация только ранее введённых механик.** Новых механик в Э-уровнях нет; пак 10 — целиком комбо-пак без новых вводов.
- **Босс → передышка:** экзамен на 8–9-м уровне пака, 10-й — лёгкий. Пак 10: передышка стоит перед финальным блоком (96 Э → 97 О → 98–100 финал).
- **Классификация сложности — easy/medium/hard + интервал, не точечные числа** (PROGRESSION §5): внутри пака easy = ниже медианы пака, hard = p75+. Границы ведер — предварительные до первых живых данных (§3.5).
- **На швах размера (паки 5 и 8) плотность формально проседает на 0,02** — осознанно: число развилок прыгает 11 → 13 → 20, и новый размер сам читается как шаг сложности. Внутри шва рампа должна быть монотонной, а не «в среднем по пакам».
- **Undo/restart в один тап** (PROGRESSION §2: ошибки — топливо ментальной модели) — особенно на T-уровнях с новой механикой.
- Внутри пака порядок монотонный по decoy/cell; `score` больше не ключ сортировки (§3, п.1).

Итого новых механик сверх стенок: **8** (М4, М12, М11, М1, М2, М7, М10, М8) — требование FR-6 «минимум 2» перекрыто; в резерве второго прохода М3, М5, М6, М9, после запуска — М13; М14 не берём; М15 — генераторная, не игровая.

## 3. Рампа без новых механик (дешёвый трек) — шаг 1 по PROGRESSION §6

1. **Заменить целевую функцию.** Выкинуть из ключа `nodes` (комбинаторика, не ощупь) и `walls` (награда за смягчение). Ключ ведра: `decoy/cell` (главный, r = 0,95) → `развилок` → `straightDecoys` → `maxGap` полосой. Один скрипт, клиент не трогается.
2. **Раскладка флажков — оптимизировать, а не рандомить.** Ложные ходы аддитивны по флажкам: `decoys(K) = D0 − Σ cost(флаг)`, где `cost[клетка]` = сколько раз клетка была бы допустимым ложным ходом. Оптимальная раскладка при фиксированном K — K−2 самых «неуловимых» клеток решения. `[замерено: +20–25 % decoy/cell при том же числе флажков]`
3. **Стенки — точечные, а не «0–6»** (кандидат PROGRESSION #1 в рабочей форме). Стена ставится ровно на первое расхождение с найденным дубликатом решения. `[замерено: 5×5 → 2 стенки, 0,50, единственность 100 %; 6×6 → 4–5, 0,571, 100 %; 7×7 → 9–10, 0,625, 64–76 %]` Для 7×7 поднять потолок стенок до 12 и повторять попытку с другой змеёй.
4. **Плотность флажков — непрерывная ручка, а не функция размера** (кандидат PROGRESSION #2, «редкие флажки»): 4×4 → 4, 5×5 → 5–8, 6×6 → 6–10, 7×7 → 7–12. Упирается в приёмку при равномерной раскладке (7×7 с 6–8 флажками — 0 из 400); с п.2 приёмка восстанавливается целевым перебором.
5. **Полосы `maxGap` по пакам:** 6–7 (П1–2) → 7–8 (П3–4) → 8 (П5) → 8–9 (П6) → 9–10 (П7) → 9 (П8) → 9–10 (П9) → 10–11 (П10). Не «чем больше, тем лучше»: 6 = обучающий, 11+ = «где я?» — только в экспертных паках.
6. **Ручка «искушения» (`straightDecoys`)** — ложные ходы, продолжающие текущее направление («пойду прямо»): сейчас не контролируется, медиана 1,5 (4×4) → 7 (7×7), разброс 0–14. Минимумы: ≥3 (П3), ≥5 (П5), ≥7 (П8), ≥9 (П10). Считается по решению бесплатно, генерируется отбором кандидатов.
7. **Размер — событие, а не конвейер.** 7×7 ≤ 30 уровней; на входе в новый размер стенок 2–4 (замерено: 6 стенок на входе в 7×7 уронили плотность ниже предыдущего пака).
8. **Что не делать:** гнать `solverNodes` вверх (выше ~50k на 6×6 — это +поиск без +ощупь и страшная приёмка); ставить стенки «для вида»; сортировать пак по `score`.

**Пороги по пакам (медианы) — сводно:** decoy/cell 0,37 → 0,63; развилок 5 → 24; straightDecoys 1 → 9; maxGap 6 → 11; стенок ≤ 1 → 5; nodes 150 → 65 000. Жёсткий инвариант на всех уровнях: решений ровно 1 (selftest-гейт уже есть).

### 3.5 Телеметрия и калибровка (PROGRESSION §5)

Прокси-метрики настраиваются офлайн, но приёмка FR-6 — **рост медианного времени от пака к паку**; без живых данных границы ведер остаются экспертными. Что нужно:

- **Собирать на уровень:** время от первого хода до победы, число подсказок, число рестартов/откатов (это и есть «attempts»), признак «ушёл с уровня не решив» → уровень бросания; агрегаты — % дошедших до пака и pass rate.
- **Метрика сложности = attempts per complete / pass rate** (PROGRESSION §5), классификация easy/medium/hard + интервал. Модель склонна завышать лёгкое и занижать хард — поэтому не точечные числа.
- **Дешёвый старт прямо сейчас:** кнопка подсказки уже в игре (rewarded) → счётчик подсказок на `level_id` даёт первый сигнал «где бились» даже без времени. Это ~10 строк.
- **Куда писать:** в сейв-схему добавить `stats` (Supabase `progress jsonb`) или отдельный лёгкий лог-эндпоинт на Bothost. Нужно решение по объёму/приватности — см. вопрос 1.
- **Калибровка после первого среза:** регрессия `время ≈ a·(развилок) + b·(straightDecoys) + c·maxGap + d`; границы ведер двигать по rolling window (PROGRESSION §5), а не разовым пересчётом — иначе калибровка по устаревшим игрокам.

## 4. Топ-3 ставки

1. **Перезапечь 100 уровней генератором v2** (шаг 1 по PROGRESSION §6: оптимизированные флажки + точечные стенки + пак-полосы + teach-гейты). Эффект: +20–25 % плотности ложных ходов при том же поле, монотонная рампа по пакам **без единой правки клиента**, единственность сохраняется (100 % на 5×5/6×6). Сложность: S–M — один скрипт (`gen-levels.mjs`) + повторное запекание и selftest.
2. **«Проёмы» (М1, кандидат PROGRESSION #5) — пак 5.** Эффект: первый за игру тип решения, которого нет в текущем дереве (обязательство без права возврата), и единственный из их кандидатов, который **добавляет** ложные ходы. Сложность: M — фильтр направления в DFS + стрелка на ребре + целевой перебор раскладки.
3. **«Форма поля» (М4) — пак 2.** Эффект: «новое» на каждом шаге при нуле новых правил, самая дешёвая правка (маска клеток), даёт перешейковую ошибку, которая видна через 6 ходов. Сложность: S.

**Ранжирование остальных кандидатов по одному критерию «добавляет ли развилки»:**
- добавляют (усилители): М10 мостики, М7 лимит поворотов, М8 стрелки входа;
- нейтральны (флейвор/новизна): М4 форма, М12 дыры, М2 сквозные, М3 уголки, М5 две нити;
- сужают дерево (подсказки, не усилители): М11 обязательные клетки (PROGRESSION #3), М6 близнецы, М1 в части случаев — поэтому паки с ними добирают плотность по §3 п.2–3;
- кандидат PROGRESSION #2 (редкие флажки) — усилитель, но это полоса maxGap, а не механика: входит в §3 п.4–5.

**Выкинуть:**
- **Рост поля как основной рычаг.** 7×7 дороже всех по приёмке (0 из 400 при разрежении флажков), риск мелких клеток на телефоне. 30 уровней 7×7 — потолок, не «продолжение лесенки».
- **Случайные стенки как «сложность»** — замерено: смягчают, а `score` их ещё и награждает.
- **Порталы через центр (М14, PROGRESSION #4 в чистом виде)** — заменены мостиками через край (М10): тот же эффект на графе, без разрыва линии.
- **Крест (М13)** — дороже всех в реализации, ломает модель «гамильтониан + visited»; в бэклог после запуска.
- **Опора на `solverNodes` и `maxGap` как на главные метрики** — описывают объём перебора, а не остроту решения.

## Приложение: воспроизводимость и генератор v2

**Логи прогонов:** `work/analysis.txt` (метрики 100 уровней), `work/tempting2.txt` (разбор ложных ходов по типам, mustTurnLive), `work/trap.txt` (глубина ложных ходов — сатурируется, в ведра не годится), `work/experiments.txt` (ручки: флажки × стены × размер), `work/placement.txt` (оптимизация раскладки, потолки по размерам), `work/targeted2.txt` (точечные стенки), скрипты `work/*.mjs` + `work/crosscheck.py`.

**Что менять в `gen-levels.mjs` (ставка №1):**

```js
// 1) cost[клетка] — сколько раз клетка была бы допустимым ЛОЖНЫМ ходом (по решению)
function decoyCosts(size, solution) {
  const cost = new Array(size * size).fill(0);
  const visited = new Set([solution[0]]);
  for (let i = 1; i < solution.length; i++) {
    const head = solution[i - 1], correct = solution[i];
    for (const n of gridNeighbors(size, head))
      if (!visited.has(n) && n !== correct) cost[n]++;
    visited.add(correct);
  }
  return cost;
}

// 2) флажки: K-2 самых «неуловимых» клеток решения вместо равномерной раскладки
function optimalWaypoints(solution, cost, K) {
  const picks = [];
  for (let p = 1; p < solution.length - 1; p++) picks.push([p, cost[solution[p]]]);
  picks.sort((a, b) => a[1] - b[1]);
  const positions = [0, ...picks.slice(0, K - 2).map(x => x[0]).sort((a, b) => a - b), solution.length - 1];
  const numbers = {}; positions.forEach((p, i) => { numbers[solution[p]] = i + 1; });
  return { numbers, positions };
}

// 3) стенки: не «randInt(bucket.walls)», а пока решатель видит >1 решение —
//    стенка на первое расхождение с уже найденным решением, ребро min(cost[a]+cost[b])
function sealUniqueness(size, numbers, solution, cost, maxWalls = 12) {
  const walls = [];
  for (let guard = 0; guard < maxWalls * 2; guard++) {
    const res = solvePaths(size, numbers, walls, solution[0], 2);   // до 2 путей
    if (res.found.length === 1) return { ok: true, walls };
    const keep = new Set(res.found[0].slice(1).map((c, i) => edgeKey(res.found[0][i], c)));
    const cands = new Set();
    for (const other of res.found.slice(1))
      for (let i = 1; i < other.length; i++) {
        const e = edgeKey(other[i - 1], other[i]);
        if (!keep.has(e)) cands.add(e);
      }
    if (!cands.size || walls.length >= maxWalls) return { ok: false, walls };
    let best = null, bs = Infinity;
    for (const e of cands) { const [a, b] = e.split(':').map(Number);
      if (cost[a] + cost[b] < bs) { bs = cost[a] + cost[b]; best = e; } }
    const [a, b] = best.split(':').map(Number); walls.push([a, b]);
  }
  return { ok: false, walls };
}

// 4) ведро: ключ = decoy/cell → развилок → straightDecoys → maxGap полосой;
//    nodes и walls из ключа убрать, walls > 0 — только результат sealUniqueness.
// 5) teach-гейт: для T-уровней решать с выключенной механикой → 0 решений, иначе брак.
// 6) гейты приёмки на пак-полосу (медианы §2) + инвариант «ровно 1 решение».
```

Проверенные ориентиры приёмки: 5×5 → 2 стенки (100 % случаев), 6×6 → 4–5, 7×7 → 9–10 и 64–76 % доходят до единственности (для 7×7 держать `maxWalls = 12` и повтор с другой змеёй).
