# Спецификация для реализации (Агент)

Твоя задача — реализовать исправления из таблицы аудита (Пункт 1 и Пункт 5) и механизм сброса кэша. Проект состоит из Python бэкенда (`server.py`) и `index.html`. Тебе не разрешается устанавливать сторонние библиотеки (`server.py` использует только стандартную библиотеку Python). Изменения не должны ломать обратную совместимость с сохранениями пользователей.

## Пункт 1: Кэширование статических файлов (P0-critical)

### Проблема:
В файле `server.py` в функции `serve_static` заголовки кэширования для статики настроены неэффективно.
Текущий код отдает: `Cache-Control: public, max-age=0, must-revalidate` для всех файлов.

### Требования к реализации:
1. Найди функцию `serve_static` в `server.py` (примерно строка 234).
2. Замени логику установки `Cache-Control`:
    - Для файлов `index.html` и `shag.html` заголовок должен быть: `Cache-Control: no-cache, must-revalidate`.
    - Для остальных статических файлов (особенно `levels.build.json`): `Cache-Control: public, max-age=31536000, immutable`.
3. Реализуй эту логику через проверку переменной `name`.

## Важное дополнение: Механизм Cache Busting для уровней

Так как мы добавляем жесткое кэширование (`immutable`, 1 год) для статических файлов, файл `levels.build.json` осядет в кэше браузеров игроков навсегда. Если мы обновим уровни (изменим содержимое файла на диске сервера), игроки со старым кэшем не увидят эти изменения, пока не очистят кэш вручную.
Чтобы решить эту проблему, необходимо внедрить **Cache Busting** (сброс кэша при помощи изменения URL). Серверная часть в `server.py` (`path.lstrip("/").split("?")[0]`) уже готова к этому и игнорирует query-параметры. Нужно поменять логику на клиенте.

### Требования к реализации (Cache Busting):
1. Открой `index.html`.
2. Найди строку определения пути к файлу: `const LEVELS_URL = 'levels.build.json';`
3. Чтобы каждый релиз игры запрашивал свежий файл уровней (но при этом кэшировался жестко до следующего релиза), добавь к URL параметр с версией или датой релиза. Для простоты и автоматизации, если у нас нет пайплайна сборки, можно привязать версию к параметру загрузки страницы или захардкодить версию в HTML.

**Инструкция для кода:**
Измени строку на `const LEVELS_URL = 'levels.build.json?v=2026-09-20';` (используй текущую или логичную дату/версию).
В будущем, при обновлении `levels.build.json`, разработчику нужно будет изменить эту версию в `index.html` (HTML-файл будет скачан заново, так как у него `no-cache`, и браузер увидит новый URL `?v=новая_версия`, скачав обновленный JSON и закэшировав его на год).

### Проверка работоспособности:
- После внесения всех изменений запусти локальный сервер: `python3 -m http.server`
- Открой в браузере `http://localhost:8000/?selftest=1`
- Убедись, что все тесты проходят без ошибок и загружается интерфейс, а в Network вкладке `levels.build.json` скачивается с новым параметром `?v=...`.
