# Документация проекта Шаг

Этот файл предназначен для другого AI-агента, который будет поддерживать или расширять проект. Читайте его перед изменением `index.html`.

## 1. Краткое описание

`Шаг` - самостоятельная ежедневная головоломка для VK Mini Apps в духе LinkedIn Zip. Название короткое, русское и не повторяет название референса.

Игрок должен:

1. Начать с клетки с числом `1`.
2. Соединять числа по порядку: `1`, `2`, `3` и так далее до `8`.
3. Заполнить все 36 клеток поля размером 6 x 6.
4. Ходить только вверх, вниз, влево или вправо.
5. Не пересекать темные стенки.
6. Не посещать одну клетку дважды, кроме возврата назад по уже нарисованному пути.

В день доступна только одна задача. Уровень определяется текущей локальной датой пользователя. Завершенный уровень нельзя начать заново или пройти повторно.

## 2. Структура проекта

В проекте должен оставаться один основной файл:

```text
index.html              Главная страница, стили, SVG, разметка, VK Bridge и JavaScript
PROJECT_DOCUMENTATION.md  Эта документация для AI-агентов
```

Не создавайте `package.json`, React-компоненты, сервер или отдельные JS/CSS-файлы, если пользователь прямо не попросит изменить архитектуру. VK Bridge подключается CDN-скриптом прямо в head.

## 3. Запуск

### Локальный запуск

Откройте `index.html` двойным кликом или через локальный статический сервер.

Пример локального сервера:

```bash
python3 -m http.server 8000
```

Затем откройте `http://localhost:8000/`.

### Зависимости

Внешние зависимости загружаются из CDN:

- Tailwind CSS Browser v4: `https://cdn.jsdelivr.net/npm/@tailwindcss/browser@4`
- Шрифт Golos Text: Google Fonts

Основная игра, SVG-иконки и CSS написаны прямо в `index.html`. Если CDN недоступен, браузер использует системный шрифт, а большая часть интерфейса продолжает работать.

## 3.1. Адаптация под VK Mini Apps

В head подключен официальный браузерный билд VK Bridge:

```html
<script src="https://unpkg.com/@vkontakte/vk-bridge/dist/browser.min.js"></script>
```

До загрузки игрового JavaScript вызывается обязательное событие:

```javascript
vkBridge.send('VKWebAppInit', {});
```

Состояние интеграции доступно в `window.vkMini`:

```javascript
{
  bridge,       // объект VK Bridge или null
  active,       // true после успешного VKWebAppInit
  initialized,
  user,         // результат VKWebAppGetUserInfo
  initPromise
}
```

Вспомогательные функции в `index.html`:

- `vkSend(event, params)` - отправить событие VK Bridge после инициализации;
- `setupVKMiniApp()` - включить VK-режим, настроить системные панели и получить профиль;
- `vkHaptic(type)` - вызвать тактильный отклик на мобильном VK-клиенте;
- `shareInVK()` - вызвать `VKWebAppShare`;
- `showVKInvite()` - вызвать `VKWebAppShowInviteBox`;
- `showVKLeaderboard()` - вызвать `VKWebAppShowLeaderBoardBox`.

Используемые события VK Bridge:

- `VKWebAppInit` - обязательная инициализация;
- `VKWebAppGetUserInfo` - имя и идентификатор пользователя;
- `VKWebAppSetViewSettings` - светлая тема системных панелей;
- `VKWebAppShare` - нативная отправка ссылки;
- `VKWebAppShowInviteBox` - приглашение друзей;
- `VKWebAppShowLeaderBoardBox` - нативная таблица результатов;
- `VKWebAppAllowNotifications` - разрешение на уведомления VK;
- `VKWebAppCopyText` - копирование через VK Bridge;
- `VKWebAppTapticNotificationOccurred` - успех, ошибка или предупреждение.

В обычном браузере VK Bridge не должен ломать игру: инициализация отклоняется, `vkMini.active` остается `false`, после чего используются обычные Web API и ручной локальный рейтинг.

В VK-режиме верхняя внутренняя навигация скрывается. Это намеренно: правый верхний угол мини-приложения зарезервирован нативной панелью VK. Действия доступны из основного контента и модальных окон.

Разрешение `VKWebAppAllowNotifications` само по себе не планирует отправку сообщений. Для настоящих ежедневных уведомлений после закрытия приложения нужен сервер сообщества или backend. В автономной версии это разрешение сохраняется как настройка, а календарь `.ics` остается надежным fallback.

## 6. Игровая логика

### Главные константы

```javascript
const SIZE = 6;
const CELL_COUNT = SIZE * SIZE;
const STORAGE_KEY = 'shag.daily.v1';
const LEGACY_STORAGE_KEY = 'zip.daily.v1';
```

Клетка хранится как одно число от `0` до `35`:

```text
cell = row * 6 + column
row(cell) = Math.floor(cell / 6)
col(cell) = cell % 6
```

### Генерация задачи

Главная функция: `makePuzzle(key)`.

Она:

1. Вычисляет детерминированный seed из строки даты.
2. Создает путь, проходящий по всем 36 клеткам.
3. Перемешивает путь детерминированным способом, не теряя связность.
4. Размещает числа `1` - `8` на восьми позициях правильного решения.
5. Создает несколько стенок, но никогда не блокирует сгенерированный правильный путь.
6. Возвращает:

```javascript
{
  day,        // YYYY-MM-DD
  solution,   // массив из 36 клеток правильного пути
  numbers,    // Map<cell, number>
  walls,      // пары клеток, разделенные стенкой
  blocked,    // Set ключей вида "a:b"
  neighbors   // доступные соседи каждой клетки с учетом стенок
}
```

Один и тот же `key` всегда должен давать одну и ту же задачу. Не используйте `Math.random()` внутри `makePuzzle`, иначе разные вкладки будут получать разные уровни.

### Проверка пути

Главная функция: `validPath(path, data, complete = false)`.

Она проверяет:

- первый элемент равен стартовой клетке решения;
- нет повторных клеток;
- соседние клетки действительно соседние;
- путь не проходит через стенку;
- числа встречаются строго по порядку;
- число `8` появляется только в последней клетке;
- при `complete === true` путь содержит все 36 клеток.

Не убирайте эту проверку при добавлении новых способов управления. Любой ввод должен в итоге проходить через `attemptCell()` или эквивалентную безопасную проверку.

### Ввод пользователя

Поддерживаются:

- мышь;
- touch/pointer events;
- клик или нажатие на соседнюю клетку;
- стрелки клавиатуры;
- `Backspace` или `Ctrl/Cmd + Z` для отмены;
- `P` для паузы;
- Enter и Space описаны в интерфейсе как стартовые клавиши, но основной доступный путь движения реализован через стрелки.

Основные функции:

- `attemptCell(cell, quiet)` - добавить клетку в путь или показать ошибку.
- `moveToward(target, quiet)` - обработать протягивание через несколько клеток по прямой.
- `undo()` - удалить последний шаг.
- `togglePause(force)` - поставить игру на паузу или продолжить.
- `showReset()` - показать подтверждение очистки текущего пути.
- `showHint()` - показать подтверждение подсказки и подсветить следующий шаг.
- `finishGame()` - заблокировать уровень, сохранить результат и открыть результат после анимации.

### Таймер

Таймер хранится в `game.seconds`.

- `syncClock()` обновляет время через `performance.now()`.
- Время идет только когда путь уже начат, игра не на паузе, окно видно и не открыт диалог.
- После победы время округляется вверх до целой секунды.
- После победы таймер больше не увеличивается.
- При скрытии вкладки незавершенная игра автоматически ставится на паузу.

Не заменяйте `performance.now()` на частый `Date.now()`-инкремент: это может давать неверное время при переключении вкладок.

## 7. Состояние и localStorage

Состояние хранится под ключом:

```text
shag.daily.v1
```

Общий формат:

```javascript
{
  version: 1,
  profile: {
    id: 'уникальный-id',
    name: 'имя для рейтинга'
  },
  days: {
    'YYYY-MM-DD': {
      path: [],
      seconds: 0,
      hints: 0,
      hint: null,
      completed: false,
      completedAt: null,
      promptShown: false
    }
  },
  friends: [],
  reminder: {
    enabled: false,
    platform: 'browser',
    time: '19:00',
    lastSent: '',
    calendarDownloaded: false
  }
}
```

В памяти текущие переменные:

- `state` - все сохраненные данные;
- `today` - текущий ключ даты;
- `puzzle` - задача для `today`;
- `game` - прогресс сегодняшней задачи;
- `paused` - текущая пауза;
- `focusedCell` - текущая клавиатурная клетка.

Главные функции сохранения:

- `loadState()` - безопасно читает localStorage.
- `sanitizeState(source)` - отбрасывает поврежденные данные.
- `restoreGame(source, data)` - восстанавливает только допустимый путь.
- `persist()` - сохраняет данные и защищает завершенный результат от перезаписи старой вкладкой.
- `queueSave()` - отложенное сохранение после изменения пути.

При изменении формата добавляйте новую версию, например `shag.daily.v2`, либо делайте явную миграцию. При переименовании `Шаг` старый ключ `zip.daily.v1` переносится в новый автоматически. Не меняйте структуру молча.

## 8. Смена дня

Функция `rollDay()` вызывается периодически и при возвращении во вкладку.

Она:

1. Сравнивает текущую дату с `today`.
2. Сохраняет старую игру.
3. Создает новый `puzzle`.
4. Восстанавливает новый `game` из `state.days[currentDate]`.
5. Перестраивает поле через `buildBoard()`.
6. Обновляет интерфейс через `render()`.

Дата считается локальной датой пользователя, а не UTC. Для вычисления соседнего дня используется `shiftDay()`.

## 9. Серия

Функция `streak()` считает непрерывную серию от сегодняшнего дня или вчерашнего дня.

Функция `renderStreak()` обновляет:

- число дней серии;
- описание серии;
- семь кружков недели;
- состояние кнопки напоминания.

Если пользователь пропустил день, серия начинается заново. Не вычисляйте серию по количеству завершенных уровней: важна именно непрерывность дат.

## 10. Результаты и друзья

После завершения уровня:

1. Открывается модальное окно `showResult()`.
2. Пользователь видит время, число подсказок и серию.
3. Приложение спрашивает, хочет ли пользователь узнать свое место среди друзей.
4. Кнопка `Узнать своё место` открывает `showFriends()`.

Это требование важно: не удаляйте вопрос о месте среди друзей из окна результата.

### Профиль

Имя хранится локально в `state.profile.name`. Оно нужно только для отображения в присланном результате.

### Код результата

`makePacket()` создает компактный объект результата:

```javascript
{
  v: 1,
  id,
  n,       // имя
  d,       // дата
  done,
  t,       // время в секундах
  h,       // количество подсказок
  s,       // серия
  p,       // полный путь только для завершенного результата
  f        // число заполненных клеток
}
```

`encodePacket(packet)` кодирует JSON в UTF-8 Base64URL и добавляет префикс `SHAG1-`. Для обратной совместимости `readPacket()` также принимает старый префикс `ZIP1-`.

`readPacket(text)` умеет найти код внутри:

- чистого кода;
- текста сообщения;
- URL с hash `#shag=...`;
- старый URL с hash `#zip=...`.

`validatePacket(packet)` обязательно проверяет:

- версию;
- id;
- имя;
- дату;
- время и число подсказок;
- полный корректный путь для завершенного результата.

Не доверяйте данным из URL или сообщения друга без `validatePacket()`.

### Локальный рейтинг

Рейтинг не является серверным. Результат друга добавляется вручную через раздел `Добавить результат друга`.

В текущий рейтинг попадают только завершенные результаты друзей за сегодняшнюю дату. Сортировка:

1. меньшее время;
2. при равном времени меньшее число подсказок;
3. затем локальный игрок и имя.

Функции:

- `todayLeaders()` - подготовить и отсортировать список;
- `addFriend(packet)` - добавить или заменить результат друга;
- `showFriends()` - отрисовать рейтинг, профиль и импорт.

Если нужен настоящий общий рейтинг между пользователями, потребуется сервер, база данных и серверная валидация результата. Один HTML-файл не может надежно реализовать это.

## 11. Поделиться в соцсетях

Функция `showShare()` показывает:

- Telegram share URL;
- VK share URL;
- системный `navigator.share`, если он доступен;
- копирование текста;
- копирование кода `ZIP1-...`;
- скачивание PNG-картинки результата.

`publicBase()` возвращает URL страницы только для `http`/`https`. Для `file://` и localhost URL-ссылка намеренно отключается, потому что она не будет полезна другому пользователю.

На опубликованном сайте ссылка имеет вид:

```text
https://example.com/index.html#zip=ZIP1-...
```

При открытии страницы `receiveSharedLink()` читает hash, валидирует пакет и показывает приглашение.

Не вставляйте пользовательские имена в `innerHTML` без `escapeHTML()`. В текущем коде имя друга экранируется перед отображением.

## 12. Напоминания

Есть два варианта:

### VK Mini Apps

Если `vkMini.active === true`, кнопка напоминания вызывает `VKWebAppAllowNotifications`. Выбранное время сохраняется в `state.reminder.platform = 'vk'`, но backend всё равно нужен, чтобы сообщество отправляло запланированное сообщение после закрытия мини-приложения.

### Notification API

Кнопка `Напомнить о новой игре` вызывает `showReminder()`.

`enableReminder()`:

- проверяет безопасный контекст;
- просит разрешение только после клика пользователя;
- сохраняет выбранное время;
- отправляет уведомление, если вкладка открыта и браузер не приостановил ее.

### Календарь

`downloadCalendar()` создает `.ics` с ежедневным событием и alarm.

Это основной вариант напоминания при закрытом браузере. Файл нужно открыть и подтвердить в календарном приложении.

Ограничение нельзя маскировать: полноценный background push требует HTTPS, service worker, push subscription и сервер, который отправляет push-сообщения. Не обещайте полноценный закрытый push в автономном `index.html`.

## 13. Диалоги

Все модальные окна используют один `<dialog id="appDialog">`.

`openDialog(kind, content, centered)`:

- сохраняет элемент, который был в фокусе;
- меняет содержимое `#modalContent`;
- блокирует прокрутку body;
- переводит фокус в заголовок модалки.

Типы `modalKind`:

- `result` - победа;
- `friends` - рейтинг;
- `share` - отправка;
- `hint` - подтверждение подсказки;
- `reset` - подтверждение сброса;
- `reminder` - напоминание;
- `tutorial` - пошаговое обучение;
- `about` - информация о проекте;
- `invitation` - входящий результат друга;
- `copy` - ручное копирование.

При добавлении нового диалога:

1. Используйте `openDialog()`.
2. Добавьте `id="modalTitle"` для заголовка.
3. Присоедините обработчики сразу после `openDialog()`.
4. Не добавляйте новый `<dialog>` без необходимости.
5. Проверьте возврат фокуса после закрытия.

## 16. Сброс данных для ручного теста

В DevTools выполните:

```javascript
localStorage.removeItem('shag.daily.v1');
localStorage.removeItem('zip.daily.v1');
location.reload();
```

Это удаляет:

- текущий прогресс;
- серию;
- имя;
- импортированные результаты друзей;
- настройки напоминаний.

## 17. Правила безопасных изменений

Перед изменением:

1. Прочитайте этот файл.
2. Найдите нужную функцию по имени, а не редактируйте случайный участок.
3. После изменения запустите `?selftest=1`.
4. Проверьте, что страница по-прежнему открывается без сборки.

Нельзя:

- заменять ежедневный seed случайным значением;
- доверять импортированному пути без `validatePacket()`;
- сохранять HTML от пользователя напрямую без `escapeHTML()`;
- удалять ограничение одной завершенной задачи в день;
- делать таймер активным во время паузы, скрытой вкладки или модалки;
- обещать общий рейтинг или закрытый push без сервера;
- удалять вопрос о рейтинге друзей после каждого завершенного уровня;
- добавлять серверные URL, токены или персональные данные в `localStorage`;
- ломать мобильное touch-управление, фокус клавиатуры или reduced motion.

## 18. Рекомендуемый порядок расширения

Если пользователь попросил новую функцию:

1. Определите, относится ли она к игре, результатам, напоминаниям или интерфейсу.
2. Добавьте состояние в `freshState()` и `sanitizeState()`, если данные должны сохраняться.
3. Добавьте UI рядом с существующей смысловой областью, а не новую конкурирующую панель.
4. Добавьте отдельную функцию действия.
5. Подключите обработчик в одном месте.
6. Обновите `render()` или специализированный `render...()`.
7. Добавьте самопроверку для новой логики.
8. Обновите этот документ, если меняется формат данных или ограничение платформы.

## 19. Известные ограничения

- Один файл не может надежно реализовать централизованный рейтинг друзей.
- Notification API требует HTTPS или localhost и обычно работает только при открытой вкладке.
- Для фоновых push нужен service worker и сервер.
- Состояние хранится только в localStorage текущего браузера.
- Если пользователь очистит данные сайта, прогресс и серия исчезнут.
- Прямые кнопки Telegram/VK полноценно полезны после публикации файла по HTTP/HTTPS.
- PNG в canvas использует демонстрационную мини-композицию поля, а не точное изображение текущего уровня. Это сделано намеренно, чтобы не раскрывать полный путь решения в публикации.
