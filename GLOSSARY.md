# Словарь «Зигзага»

Канон: в доках и UI — «числа» (`numbers` — только в коде и JSON).
Источники: `PROJECT_DOCUMENTATION.md`, `PIKABU_PLAN.md`, `PROGRESSION.md`, `result research/ZIGZAG_RAMP.md`.

## Ядро

**Числа** — клетки с цифрами 1–N, которые надо соединить по порядку. Линия стартует с 1 и финиширует на N, покрыв всё поле.

**Гамильтониан** — победный путь: линия проходит через каждую клетку поля ровно один раз. Отсюда следствие: любая «обязательная» клетка покрывается автоматически.

**Ложный ход** — допустимый ход, не ведущий по решению. Главная метрика сложности.

**decoy/cell** — плотность ложных ходов на клетку. Ключ отбора уровней (корреляция с работой решателя r = 0,95). Рампа паков: 0,37 → 0,63.

**Развилка** — клетка решения, где у игрока ≥2 вариантов продолжения. Число развилок растёт по пакам: 5 → 24.

**straightDecoys** — ложные ходы, продолжающие текущее направление («пойду прямо»). Ручка искушения, минимумы по пакам.

**maxGap** — самый длинный отрезок решения между соседними числами. Полоса по пакам 6–7 → 10–11, не «чем больше, тем лучше».

**solverNodes** — узлы перебора DFS-решателя. Описывает объём поиска, а не остроту решения — не ключ сортировки.

**Эталон** — правильное решение уровня (поле `_solution` в `levels.json`). В билд не попадает (вычищается `build-levels.mjs`), нужен для тестов и dev-режима.

## Генератор

**Змея** — стартовый гамильтониан (змейка + backbite-перемешивание), заготовка решения до расстановки чисел и стенок.

**decoyCosts** — вес клетки: сколько раз она была бы допустимым ложным ходом. Числа ставятся на самые «неуловимые» клетки.

**optimalWaypoints** — раскладка чисел: K−2 самых неуловимых клеток решения с разбегом по отрезкам (иначе кластеризация и улёт maxGap).

**seal (опечатывание)** — точечные стенки на рёбра ложных проходов, пока решений не станет ровно 1 (`sealUniqueness`). Рёбра эталона неприкосновенны.

**Ведро сложности** — отбор уровней: ключ decoy/cell → развилок → straightDecoys → maxGap полосой. nodes и walls из ключа убраны.

**Рампа** — монотонный рост decoy/cell внутри пака и от пака к паку. Внутри пака сортировка по возрастанию.

**Шов размера** — вход в новый размер поля (паки 5 и 8). Плотность формально проседает на 0,02 — осознанно, размер сам читается как шаг сложности.

**Запекание** — офлайн-генерация 100 уровней скриптом `gen-levels.mjs` в `levels.json` + сборка `build-levels.mjs` в `levels.build.json` (без эталонов).

## Процесс

**Пак** — 10 уровней. Схема: 2 teach → 5 practice → 2 экзамен → 1 передышка. Пак 10 — комбо-пак без новых вводов.

**T (teach)** — 2 первых уровня пака: механика в изоляции, решить можно только ею. Ровно 1 маркер механики, teach-гейт обязателен.

**P (practice)** — 5 уровней: та же механика в вариациях, 1–2 маркера.

**Э (экзамен)** — 2 уровня: комбинация только ранее введённых механик, нового нет. Правило пака должно грузить (гейт без правила — неоднозначность).

**О (передышка)** — последний уровень пака: лёгкий, на мастерство и отдых. 1 маркер.

**teach-гейт** — проверка «механика обязательна»: без правила T/Э-уровень обязан решаться не единственным путём, иначе teach проходится «не поняв» — в мусор. Для покрывающих подсказок неприменим (см. М11).

**second-level test** — проверка кандидата в механику: чем 2-й уровень с ней отличается от 1-го. Нет ответа — механика в мусор до кода.

## Механики

**М1. Проёмы (пак 5, 41–50)** — односторонние двери на рёбрах: пройти можно только в одну сторону, обратно нельзя. Статус: следующая в очереди (пак 5 пропущен, вернёмся после М2).

**М2. Сквозные клетки (пак 6, 51–60)** — на клетке с чёрточкой нельзя поворачивать: линия входит и выходит по одной прямой. Статус: в игре.

**М3. Клетки-повороты** — на клетке с уголком линия обязана повернуть. Статус: резерв (второй проход, пригодится паку 6).

**М4. Форма поля (пак 2, 11–20)** — поле не квадрат, а фигура с вырезами и перешейками; линия по-прежнему обходит все клетки. Статус: в игре.

**М5. Две нити** — числа двух цветов, внутри цвета по возрастанию, порядок между цветами свободный. Статус: резерв.

**М6. Флажки-близнецы** — два числа с одинаковым номером проходятся в любом порядке. Статус: резерв (смягчитель ритма).

**М7. Лимит поворотов (пак 7, 61–70)** — весь путь не более чем за K поворотов, K показано рядом с полем. Статус: следующая после М1.

**М8. Стрелки входа (пак 9, 81–90)** — к числу можно подойти только с указанной стороны. Статус: в очереди.

**М9. Свободный старт** — стартовое число не помечено: линия начинается с любого числа. Статус: резерв.

**М10. Мостики через край (пак 8, 71–80)** — две отмеченные клетки на краях считаются соседними, линия не рвётся. Статус: в очереди.

**М11. Обязательные клетки** — метка без номера: линия обязана пройти. Статус: удалена (FR-11) — покрывающая подсказка без логического смысла, гамильтониан проходит через точку по построению. Не использовать.

**М12. Дыры (пак 3, 21–30)** — закрытые клетки, заходить нельзя. Статус: в игре.

**М13. Крест** — в отмеченной клетке линия проходит над собой (клетка дважды). Статус: бэклог после запуска (ломает модель «гамильтониан + visited»).

**М14. Порталы** — телепорт через центр, линия визуально рвётся. Статус: не брать (заменены М10).

**М15. Стена-улика** — не механика, а ручка генератора: стенки точно на рёбра ложных проходов (= `sealUniqueness`). Статус: работает всегда.
